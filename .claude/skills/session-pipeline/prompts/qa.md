# Промпт QA-агента (Этап 4)

Используется в Agent (model=sonnet, run_in_background=true). Подставь `{N}` — номер сессии, `{SEGMENT_NUM}` (1/2/3), `{OFFSET}`/`{LIMIT}` — диапазон строк.

---

Ты делаешь финальную QA-вычитку очищенного транскрипта PF2e-сессии кампании «Азланти», сессия {N}. Транскрипт уже прошёл черновую очистку 9 агентами + структурные правки. Твоя задача — найти оставшиеся точечные косяки.

## Файл и сегмент

Прочитай **только строки {OFFSET+1}-{OFFSET+LIMIT}** файла:
`C:\DND\sync\Sync\Obsidian\PF2e\Кампейны\Азланти\Sessions\Session{N}\ПС{N}_transcript.md`

Используй `Read` с `offset={OFFSET}, limit={LIMIT}`.

## Что искать

### 1. WhisperX-артефакты в репликах
- Оборванные на полуслове фразы, которые точно можно восстановить по контексту
- Склеенные два слова в одно («какнадо», «вотчто»)
- Бессмысленные слова — искажения распознавания
- Слова не по смыслу (предложить замену по контексту)

### 2. Несогласованные имена (normalization могла что-то пропустить)
- «Псалом» → «Абсалом»
- «Гильдала» / «Гедала» → «Гельдала»
- «Аббадар» → «Абадар»
- «Аарадан» / «Арадан» → «Ароден»
- «Аркариум» / «Арканомириум» / «Арканариум» / «Оркнариум» → «Арканамириум»
- «Амидай» / «Амедай» / «Айодан» → «Иомедай»
- «Голдфри» → «Галфри»
- «Доскари» / «Эскарри» → «Дескари»
- «Миндев» → «Мендев»
- «Анканта» (как имя) → «Анканто»
- «форазмы» → «Ферасмы»
- «Псекира» (как оружие) → «секира»
- «Ургатуа» → «Уртагоа»
- «Саквротский» → «Сакворотский»
- «Альдрик» → «Алдрик»
- «Хайден Кайдан» → «Кайдан»
- «Ангвинор» (как сын Гельдалы) → «Унгвинор»
- «Дом Ормуз» → «Дом Ормуз»
- «Дом Сени Грации» → «Дом Сени и Грации»
- «сераяне» / «сераян» → «Сираен» (имя хозяйки)

### 3. Формат говорящего
- Должно быть `**Имя (роль):**`. Если просто `**Имя:**` или пропущен префикс — пометь.
- Действие в блоке речи или наоборот — пометь.
- IC обёрнута в `*[OOC: ...]*` или OOC как IC — пометь.

### 4. Орфография/пунктуация
- Только явные опечатки и пропущенные знаки. Стиль не править.

### 5. Логические косяки
- Реплики двух людей в одном `**Имя:**`-блоке.

### 6. Особое внимание к стыкам и финалу
- На стыках чанков (там, где сцена меняется) — проверь, нет ли дублей и оборванных фраз.
- В пост-сессионных OOC-блоках проверь, не повторяется ли что-то из основной части.

## Что НЕ трогать

- **Стиль реплик персонажей.** Сохраняй характерную речь (запинки, междометия, авторские формулировки игроков).
- **Системные строки** в `*[...]*` (броски, эффекты, ЧАТ) — не правь.
- **Заголовки сцен `### ...`** — не предлагай переименование (структуру я уже подчистил).
- **Не дублируй чужие правки.** Если что-то выглядит «странно, но это игровой стиль» — не трогай.
- **Не пиши в файл** — только верни список.

## Формат вывода

```
## Сегмент {SEGMENT_NUM} (строки {OFFSET+1}-{OFFSET+LIMIT}) — список правок

### [FIX] — уверенные правки

1. Строка XXX: «...» → «...»
   Контекст: «...»
   Причина: ...
   old_string: `точная строка для Edit`
   new_string: `новая строка для Edit`

### [CHECK] — спорные, требуют человеческого разбора

1. Строка YYY: ...
```

**Каждая правка должна быть применима через Edit:** дай уникальный фрагмент `old_string` и `new_string`. Если строка не уникальна — добавь контекст (1-2 окружающих строки).

## Объём

Если правок мало (например, <10) — это нормально, текст уже неплохо очищен. Не выдумывай проблемы. Лучше короткий список реальных косяков, чем длинный список придирок.

Поехали.
