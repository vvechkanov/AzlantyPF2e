# Автописатель Книги — Архитектура v2

> Конвейер: сессия (транскрипт + рекап) → глава книги Тироса, с минимумом ручной работы Влада. Состояние: переоснащён 23.08.2026 под Opus 5, пилот на С5 не проведён.

## Зачем

Влад на С4–С5 редактировал главы руками — качество выросло (С4 = 45/50, эталон), но времени сожрало столько, что процесс встал. К С18 книга отстала на 13 сессий. Цель — система, где Влад запускает пайплайн, уходит, возвращается к драфту и **вычитывает его за один-два раунда, а не за десять**.

Это и есть критерий приёмки. Не «идеальная глава с первого раза» — а «черновик, к которому у Влада полтора десятка точечных замечаний, а не полная переделка».

## Что изменилось против v1 и почему

v1 была спроектирована в июне 2026 под ограничения прошлого поколения моделей и ни разу не запускалась. Пять решений пересмотрены:

| Было (v1) | Стало (v2) | Причина |
|---|---|---|
| Эталонные фрагменты писателю не давать — «начнёт подгонять под образец» | Три эталонные сцены из С4 даются писателю всегда (`05__Эталонные_сцены.md`) | Писатель получал 7 запретов и 0 образцов. По запретам текст сужается, но голос не собирается — выходит корректный конспект. Риск копирования реален, но меньше этой беды; в эталонах прямо сказано, что переносить формулировки нельзя |
| N писателей, каждый видит только свою сцену | **Один писатель на главу**, видит транскрипт, конспект и план целиком | Изоляция сцен была обходом узкого контекста. При 1M он не нужен: транскрипт сессии — ~70–90K токенов. Слепые писатели дают ровные сцены и главу без сквозной дуги |
| Одна генерация на сцену, ориентир 400–800 слов | Писатель пишет **сцену за сценой отдельными проходами**, объём — по материалу | Сохраняет оба принципа сразу: короткая генерация держит голос живым (проверено 23.03.2026), общий контекст держит дугу главы. Раньше эти два требования конфликтовали |
| Правки применяет писатель, выдавая сцену целиком заново | Правки применяются **патчем** по тексту | «Выдай полный текст с применёнными правками» — это перегенерация. Ровно тот механизм стерилизации, от которого v1 защищалась лимитом раундов |
| Норматив главы 2500–3500 слов | Глава 5–8K слов, ориентир — материал | Сессии выросли вдвое (С0 — 125K символов, С14 — 285K). Готовые главы и так росли: С0 — 4066 слов, С4 — 5864. Сжатие живой сессии втрое даёт конспект |

Сохранено без изменений: правило одного правочного раунда, точечность правок, критик без эталонов и без контекста сессии, чекпоинты Влада, `Lessons.md` как память между прогонами.

## Роли

- **Main Author** — головной чат. Читает транскрипт, рекап, конспект Тироса, Project Instructions. Режет главу на сцены, готовит план, ведёт писателя, синтезирует критику, применяет патчи, склеивает файл. Сам прозу не пишет.
- **Писатель** — один сабагент на главу (Opus). Получает Project Instructions, эталоны, конспект Тироса, план главы и транскрипт своей сцены. Пишет сцены последовательно, по одной за сообщение.
- **Критики** — сабагенты, по одному на сцену (Opus), запускаются по мере готовности сцен, параллельно. Видят только текст сцены.
- **Final Critic** — один сабагент на склеенную главу.
- **Линтер** — `Dev/book_lint.py`, механическая проверка синтаксических запретов. Бесплатный, отрабатывает до критиков.
- **Влад** — два чекпоинта по ходу и финальная вычитка.

## Поток

```
[Сессия N: ПСN_transcript.md + ПСN_recap.md + Книга__Конспект_Тироса.md]
        ↓
MAIN AUTHOR
  читает: Project Instructions + Конспект Тироса + эталоны +
          транскрипт + рекап + Lessons.md
  производит: план главы (сцены с границами) + фактчек-вопросы +
              раундовый пересказ боёв своими словами
        ↓
⏸ ЧЕКПОИНТ 1 — Влад: план сцен, ответы на вопросы по фактуре,
              сверка боевого пересказа
        ↓
ПИСАТЕЛЬ (один сабагент, сцены последовательно)
  сцена 1 → сцена 2 → ... → сцена N
  каждая — отдельным проходом, с оглядкой на уже написанное
        ↓
  по мере готовности каждой сцены, не дожидаясь остальных:
    ЛИНТЕР (мгновенно) → КРИТИК сцены (параллельно с письмом следующих)
        ↓
MAIN AUTHOR синтезирует критику
  отсеивает ложные срабатывания (сверяет с транскриптом: «сцена рыхлая»
  бывает честным отражением рыхлого вечера)
  оформляет выжившие замечания как патчи
        ↓
  правка-замена или правка-удаление → main применяет патчем сам
  правка, требующая нового текста больше фразы → писателю, точечно
        ↓
[Если сцена сломана в принципе:]
⏸ ЧЕКПОИНТ 2 (редкий) — Влад: что не так с планом сцены
        ↓
MAIN склеивает главу → FINAL CRITIC на весь текст → патчи
        ↓
[Драфт → ⏸ ЧЕКПОИНТ 3 — Влад вычитывает]
        ↓
Правки Влада → main извлекает уроки → Lessons.md
        ↓
Конспект Тироса обновляется на эту главу
```

## Зафиксированные решения

| Решение | Обоснование |
|---|---|
| Писатель один на главу, но пишет посценно | Сквозная дуга без потери живого голоса |
| Эталоны обязательны, копирование формулировок запрещено явно | Голос ставится примером, а не списком запретов |
| Один раунд правок, не больше | Машинная переписка >2 раз стерилизует текст |
| Правки только точечные; замена/удаление — патчем силами main | Перегенерация сцены ради двух правок убивает оригинальную ткань |
| Критик не видит эталонов, брифа и контекста сессии | Свежий читательский взгляд; фильтрует main |
| Линтер отрабатывает до критиков | Синтаксические нарушения ловятся бесплатно, критик не тратит внимание |
| Объём — следствие материала | Норматив 2500–3500 устарел вместе с длиной сессий |
| Main Author — новый чат на каждую главу | Единый чат деградирует за 3–4 сессии |
| Память между прогонами — `Lessons.md` | Самое ценное — правки, которые Влад внёс руками |
| Чекпоинт 1 обязателен | Пять минут Влада спасают главу |
| Бои — только после сверки пересказа с Владом | Транскрипт боя нашпигован механикой, физическая картина за ней теряется. До реализации `pf2e-combat-chronicle` это единственное место, где человек обязателен |

## Состав папки

- `00__Архитектура.md` — этот файл
- `00__Старт_промпт.md` — точка входа для Main Author
- `01__Шаблон_брифа.md` — формат плана главы и сценового брифа
- `02__Промпт_Writer.md` — промпт писателя
- `03__Промпт_Critic.md` — промпт посценного критика
- `04__Промпт_FinalCritic.md` — промпт финального критика
- `05__Эталонные_сцены.md` — few-shot из С4
- `Lessons.md` — уроки прогонов

## Связи

- `Assistant Guides/Книга__Project_Instructions.md` — свод стиля (читают main, писатель, критики)
- `Сюжет кампании/Книга__Конспект_Тироса.md` — память рассказчика (main, писатель)
- `Dev/book_lint.py` — линтер анти-паттернов
- `Sessions/SessionN/ПСN_transcript.md` + `ПСN_recap.md` — сырьё

## Пилот

Первый прогон — **на сессии 5**. Основания: материал полный; рядом лежит эталон С4 для калибровки; и существует ручной драфт `ПС5_книга.md` (6824 слова, оборван на входе в бой), с которым машинный результат можно сравнить напрямую.

Ожидание по качеству — 38–42/50 на первой главе, 42–45 к третьей-четвёртой, когда `Lessons.md` наполнится. Обещать 45/50 с первого прогона нельзя.
