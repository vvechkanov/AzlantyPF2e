# Автописатель Книги — Архитектура

> Конвейер по превращению сессии (транскрипт + рекап) в главу книги Тироса с минимумом ручной работы Вовы. Состояние: проектирование.

## Зачем

Вова на С4–С5 редактировал главы руками — это подняло качество (С4 = 45/50, эталон по нашему разбору), но сожрало время. К С10 партия ушла вперёд, книжный пересказ застрял на С5. Цель — система, где Вова запускает пайплайн, уходит, возвращается к готовому драфту, делает финальную ручную правку.

Принципиальное ограничение: машинная переписка > 2 раз ведёт к стерилизации. Поэтому архитектура жёстко режет число итераций и опирается на **точечные правки**, а не переписывание.

## Роли

- **Main Author** — этот чат. Держит всю картину: читает транскрипт, рекап, конспект Тироса, стайлгайд. Нарезает на сцены, готовит брифы, синтезирует критику в точечные инструкции, склеивает финал.
- **Writer (×N, параллельно)** — сабагент на сцену. Получает только бриф + стайлгайд + Project_Instructions. НЕ видит остальной транскрипт, НЕ видит другие сцены, НЕ видит полный конспект Тироса.
- **Critic (×N, параллельно)** — сабагент на сцену. Получает стайлгайд + сцену + 5 критериев + «дух критика». НЕ видит эталонных фрагментов (чтобы не подгонял под образец).
- **Final Critic** — один сабагент на весь склеенный документ. Микроправки по единству тона и переходам.
- **Вова** — три чекпоинта (см. ниже).

## Поток

```
[Сессия N: ПСN_transcript.md + ПСN_recap.md + Книга__Конспект_Тироса.md]
        ↓
MAIN AUTHOR
  читает: стайлгайд + Project_Instructions + конспект Тироса +
          транскрипт + recap + Lessons.md
  производит: план сцен + бриф на каждую (с событийными бетами
              предыдущих сцен главы + сценовыми сдвигами Тироса
              + явным списком NPC сцены). Дoсье из конспекта в
              бриф НЕ копируется — писатель прочитает сам.
  отдельно: пробегает по подготовленным брифам fact-check
            глазом. Если в транскрипте видит атрибуцию реплики,
            которая смущает (немой герой говорит вслух; «моя
            рубаха» в чужом доме; жест поиска подан как реплика;
            оговорка ГМа с именами), фиксирует список «вопросов
            к Вове по фактуре» и выносит его в Чекпоинт 1
            вместе с планом и брифами.
  для боёв: если в сцене бой — main делает раундовый пересказ
            боя своими словами (без механики, без чисел), и тоже
            выносит его на Чекпоинт 1. Транскрипт боя нашпигован
            HP/бросками/именами правил, физическая картина за ними
            теряется; писатель не должен играть в реконструктора.
        ↓
⏸ ЧЕКПОИНТ 1 — Вова ревьюит план сцен и брифы + отвечает на
              fact-check вопросы + сверяет боевой пересказ
        ↓
WRITERS (параллельно, ×N)
  получают: стайлгайд + Project_Instructions + свой бриф
  пишут: одну сцену (мягкий ориентир по объёму, без жёстких рамок)
        ↓
CRITICS (параллельно, ×N)
  получают: стайлгайд + 5 критериев + дух критика + сцена
  выдают: точечную критику (этот абзац / эта фраза / это слово)
        ↓
MAIN AUTHOR синтезирует
  собирает критику + свой взгляд на целое (баланс между сценами,
  не дублируется ли мотив, не съезжает ли тон)
  выдаёт каждому writer'у ИТОГОВЫЕ ТОЧЕЧНЫЕ ПРАВКИ:
    "абзац 3, фраза X → заменить на Y"
    "удалить второе предложение в абзаце 5"
    "вставить деталь Z между предложениями 2 и 3 в абзаце 7"
  НЕ говорит "перепиши абзац" в свободной форме
        ↓
[Если критик считает, что сцена сломана в принципе:]
        ↓
⏸ ЧЕКПОИНТ 2 (редкий) — Вова получает пакет:
       старый бриф / почему он плох / новый бриф / черновик сцены
       подтверждает или обсуждает
        ↓
WRITERS вносят точечные правки (НЕ переписывают)
        ↓
MAIN AUTHOR склеивает + правит переходы
        ↓
FINAL CRITIC: один сабагент на весь документ
  выдаёт микроправки по единству тона (тоже точечные)
        ↓
MAIN AUTHOR применяет
        ↓
[Готовый драфт → ⏸ ЧЕКПОИНТ 3 — Вова финально вычитывает]
        ↓
Вова даёт фидбек → main извлекает уроки → дописывает в Lessons.md
```

## Зафиксированные решения

| Решение | Обоснование |
|---|---|
| Жёсткое правило: 1 раунд правок, не больше | Машинная переписка >2 раз стерилизует текст |
| Правки только точечные (фраза/абзац/деталь) | Переписывание блоков убивает оригинальную ткань |
| Эталонные фрагменты writer'ам и критикам НЕ давать | Они начинают подгонять под образец |
| Стайлгайд держит дух — у писателей и критиков | Это и есть единый референс |
| Полный конспект Тироса writer читает через Read целиком | Без бэкграунда писатель не знает голосовых тиков героев, канонических цитат, ограничений (немой герой не говорит вслух) и логики сцены. Прежнее решение «давать выжимку под сцену» провалилось на С4: писатели не отлавливали оговорки ГМа в транскрипте, потому что не видели общего каркаса |
| Брифы дают только: события предыдущих сцен главы (беты, без прозы) + сценовые сдвиги Тироса не из дoсье + список NPC сцены | Конспект — про знание Тироса на конец предыдущей сессии. Бриф — про то, что свежего происходит в этой главе |
| Main Author — новый чат на каждую сессию | Единый чат деградирует за 3–4 сессии |
| Контекст между сессиями — через `Lessons.md` | Аналог MEMORY.md для Claude Code |
| Чекпоинт 1 (план сцен) — обязателен | 5 минут Вовы спасает 6 криво написанных сцен |
| Чекпоинт 2 (сломанная сцена) — только когда сцена не вытягивается точечными правками | Решение через переделку брифа, не через машинную переписку |
| Если бриф пересоздан, но критик опять не доволен — сцена идёт Володе | Не пихать в третий машинный раунд |

## Состав папки

- `00__Архитектура.md` — этот файл, общий обзор
- `00__Старт_промпт.md` — **точка входа**: Вова копипастит его в новый чат, чтобы запустить Main Author
- `01__Шаблон_брифа.md` — формат брифа на сцену (ядро системы, проектируется первым)
- `02__Промпт_Writer.md`
- `03__Промпт_Critic.md`
- `04__Промпт_FinalCritic.md`
- `Lessons.md` — накапливаемые уроки между сессиями

## Связи с другими файлами

- `Assistant Guides/Книга__Стайлгайд_v2.md` — дух письма (используют writer и critic)
- `Assistant Guides/Книга__Project_Instructions.md` — промпт-обёртка (используют writer'ы)
- `Assistant Guides/Книга__Рассказчик_Тирос.md` — профиль Тироса
- `Сюжет кампании/Книга__Конспект_Тироса.md` — память Тироса (читает main author, извлекает в брифы)
- `Sessions/SessionN/ПСN_transcript.md` + `ПСN_recap.md` — исходники сессии

## Тестовый прогон

Первый прогон — на сессии 4. У нас уже есть ручной эталон (`Sessions/Session4/С4-архив.md`, оценка 45/50). Сравним машинный результат с ним. Цель первой итерации — 4.0 по нашей шкале (4.5 = почти эталон, 5.0 = маловероятно с первого захода).

## Точка входа

`00__Старт_промпт.md` — Вова копипастит его содержимое в новый чат Claude Code. Промпт говорит модели стать Main Author: что прочитать (стайлгайд, конспект Тироса, транскрипт, рекап, Lessons.md), что произвести (план сцен + брифы), и как дальше работать с writer'ами/критиками по правилам из `00__Архитектура.md`.
