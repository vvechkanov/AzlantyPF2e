# Шаблон брифа на сцену

> Бриф — единственный input writer'а помимо стайлгайда и Project_Instructions. От качества брифа зависит вся сцена. Main author готовит по одному брифу на каждую сцену.

## Принципы (важнее формы)

1. **Main делает монтаж, не интерпретацию.** Не пересказывает события своими словами — режет сырьё (транскрипт) и указывает писателю, где у Тироса каркас знания, который надо доглянуть в Конспекте.
2. **Транскрипт режется по границам сцены с запасом.** Лучше чуть больше, чем впритык. Внутри сцены ничего не вычищается — OOC, отвлечения, повторы оставляем как есть; их фильтрация — работа writer'а по стайлгайду.
3. **Конспект Тироса целиком — обязательное чтение писателя, не выжимка в брифе.** Писатель сам читает `Сюжет кампании/Книга__Конспект_Тироса.md` через Read. Дoсье в конспекте отражает знание Тироса на конец предыдущей сессии — этот файл и есть его «бэкграунд». В брифе остаются только сценовые сдвиги (свежее, что Тирос узнаёт В эту сцену впервые) и явный список NPC сцены.
4. **Писатель сцены N знает события сцен 1..N-1 этой главы — но не их прозу.** Главное поле для этого — «Место в плане главы»: туда главного редактора пишет короткий событийный список бетов по предыдущим сценам (без реплик, без описаний, без литературной ткани). Это нужно, чтобы писатель видел канон главы и не подсматривал чужой текст.
5. **Никакой подсветки «что обязательно сохранить».** Writer сам читает транскрипт и принимает решения. Main не указывает пальцем на ярчайшие моменты — это сужает писательский глаз.

## Структура брифа

Семь полей. Пять обязательных, два опциональных (помечены `[опц.]`).

### 1. Заголовок и опорное название сцены
Рабочее название по содержанию, не по нумерации. Пример: «Утро после боя: кормление пленных», а не «Сцена 2». Для writer'а — ориентир.

### 2. Место в плане главы
Какая сцена по счёту в этой главе и что вокруг.

**Что уже произошло в этой главе** (список событийных бетов по предыдущим сценам — без реплик, без описаний, только факты):
- Сцена 1: ...
- Сцена 2: ...
- ...
- Сцена N-1: ...

**После этой сцены:** [одной фразой — что будет]

Цель этого раздела — дать писателю сцены N канон главы, не отдавая ему чужую прозу. Писатель сцены 5 должен знать, что в сцене 2 Анканто удержал Микаэля и вывел из комнаты, а не догадываться по обмолвкам. Литературную ткань соседних сцен он по-прежнему не видит.

### 3. Список участников
- **PC:** [кто из партии]
- **NPC:** [кто значимый — в кадре или явно упоминается]
- **Тирос:** где находится, какой режим наблюдения (козодой на крыше / невидимка рядом / истинная форма)

### 4. Сценовые сдвиги Тироса
**Главный сдвиг этого раздела по сравнению со старой версией:** полная база знаний Тироса — это файл `Сюжет кампании/Книга__Конспект_Тироса.md`. Писатель его читает целиком через Read. В брифе мы здесь даём только то, чего там НЕТ:

- **Свежие наблюдения текущей сессии до этой сцены** — что Тирос узнал в более ранних сценах главы, чего не было в дoсье на конец предыдущей сессии. Например: «В сцене 1 Тирос впервые увидел, как Грим жмёт руку двумя сверху — это у торговцев формула серьёзного момента». Если сцена первая в главе — этот пункт может быть пустым.
- **Точечные пометки про NPC сцены**, если в дoсье Конспекта их нет вовсе (новый NPC появляется впервые), либо если ракурс важный и не очевидный из дoсье.
- **Якорные детали локации/обстоятельств**, которые писателю нужны как опорные точки сцены.

Формат — короткие буллеты. Не пересказывать дoсье из конспекта; писатель прочитает сам.

### 5. Запретные зоны
Что Тирос **не должен знать / не должен показывать** в этой сцене. Нераскрытые секреты партии, информация из других POV, спойлеры.

Если ограничений нет — пиши явно: «Нет».

### 6. Фрагмент транскрипта
Сама сцена в исходном виде, вырезанная по границам с запасом. Без чисток внутри. Под спойлером для удобства чтения брифа:

```markdown
<details>
<summary>Транскрипт сцены</summary>

[вставленный кусок транскрипта]

</details>
```

### 7. Ориентир по объёму
По стайлгайду: **одна сцена = 400–800 слов** (`Книга__Стайлгайд_v2.md`, `Книга__Project_Instructions.md`, `Книга__Рабочий_процесс.md`). На главу — 2500–3500 слов суммарно. Везде с оговоркой: объём — следствие истории, а не цель.

Дефолт для main author'а: **~600 слов** (середина диапазона). Сдвигать в стороны только если сцена явно того требует — короткая связка к 400, плотный разговор/экшен к 800.

Формулировка в брифе:
- «~600 слов» (типичная сцена)
- «~400 слов, связка, не растягивать» (короткая)
- «~800 слов, длинный разговор» (плотная)
- «по ситуации» — если main не уверен; writer тогда сам решит в диапазоне 400–800

### [опц.] 8. Заметка main author'а
Если main хочет передать writer'у что-то особенное, что не укладывается в стандартные поля — короткая заметка. Например: «эта сцена откликается на сцену 1 — параллельный мотив, имей в виду»; «писать особенно сдержанно, в главе уже было много эмоций».

Использовать редко. Большинство сцен этого поля не имеют.

### [опц.] 9. Граница сцены
Если граница неочевидна (плавный переход без смены локации/темы) — main явно отмечает: «начни с реплики Анканто „...“», «закончи на моменте, когда Гельдала выходит из дома».

### [для боевых сцен] 10. Боевой пересказ
Если в сцене есть бой — main обязательно прикладывает к брифу **свой раундовый пересказ боя в свободной форме**, согласованный с Вовой на Чекпоинте 1.

Пересказ нужен потому, что транскрипт боя нашпигован системными вставками (HP, броски, имена правил, инициатива), и за ними физическая картина теряется. Писатель не должен играть в реконструктора — это работа main'а.

Формат — раунд за раундом, без механики, без чисел, своими словами. Что в каждом раунде существенно для нарратива:
- Кто атаковал кого (особенно если на одну цель било несколько).
- Какие удары были крит/сильные, какие — рутина (крит = заметное в нарративе).
- В какой момент кто упал, кто потерял сознание, кто спас сцену.
- Особые эффекты (мутагены, реакции артефактов, превращения) — что именно сработало и от чего.
- Превращения PC в оружие/форму — кто управляет, кто держит, кто получает урон при поломке.

Без этого блока писатель боевой сцены будет придумывать механику самостоятельно и разойдётся с каноном.

## Шаблон для копирования

```markdown
## Бриф: Сцена N — [опорное название]

**Место в главе:** сцена N из M

Что уже произошло в этой главе:
- Сцена 1: ...
- Сцена 2: ...
- ...

После этой сцены: [одной фразой]

**Участники:**
- PC: ...
- NPC: ... (только те, кто в кадре или явно упоминается)
- Тирос: [где, в каком режиме]

**Сценовые сдвиги Тироса:**
- Свежие наблюдения текущей сессии до этой сцены: ...
- Точечные пометки про NPC сцены (если их нет в дoсье или ракурс не очевиден): ...
- Якорные детали локации/обстоятельств: ...

**Запретные зоны:** [список секретов либо «нет»]

**Ориентир по объёму:** ~600 слов (либо своё значение в диапазоне 400–800, либо «по ситуации»)

[опц.] **Заметка автора:** ...

[опц.] **Граница сцены:** ...

[если в сцене бой] **Боевой пересказ (согласован с Вовой):**
- Раунд 1: ...
- Раунд 2: ...
- ...

**Фрагмент транскрипта:**

<details>
<summary>Транскрипт сцены</summary>

[вставленный кусок]

</details>
```

## Что НЕ должно быть в брифе

- Пересказ событий своими словами (это вместо транскрипта, а не вместе)
- Указания «обязательно сохрани реплику X» (writer сам)
- Указания «убери логистику» (стайлгайд знает)
- Эталонные фрагменты прошлых глав (writer не подгоняет под образец)
- Дублирование дoсье из Конспекта Тироса (писатель его читает сам через Read)
- Транскрипт всей сессии (только нужная сцена)
- Литературная ткань соседних сцен (только событийные беты «что было»)

## Чеклист main author'а перед отправкой брифа writer'у

- [ ] Все обязательные поля заполнены
- [ ] Транскрипт-фрагмент вырезан по границам, без хвостов соседних сцен
- [ ] Внутри транскрипта ничего не вычищено (OOC, отвлечения сохранены)
- [ ] Список NPC покрывает только тех, кто в кадре или явно упоминается
- [ ] «Что уже произошло в этой главе» содержит сухие беты по предыдущим сценам, без литературной ткани
- [ ] «Сценовые сдвиги» — это ТОЛЬКО то, чего нет в дoсье Конспекта Тироса
- [ ] Запретные зоны указаны явно (или «нет»)
- [ ] Ориентир по объёму указан (число в диапазоне 400–800 либо «по ситуации»)
- [ ] Если в сцене есть бой — приложен раундовый пересказ, согласованный с Вовой на Чекпоинте 1
